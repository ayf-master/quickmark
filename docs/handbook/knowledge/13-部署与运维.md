# 13 · 部署与运维

> 目标：把 QuickMark 跑上服务器，并知道「外网打不开」时怎么排查。这是简历里「能独立上线」的硬证据。

## 13.1 三种部署形态

| 形态 | 适用 | 说明 |
|---|---|---|
| 纯 Docker | 演示/干净环境 | `docker-compose up` 起 db+redis+app |
| 服务器（当前实测） | 生产 | MySQL/Redis 用 Docker 容器，应用用宿主机 Node+PM2 |
| 本地开发 | 日常 | `npm run dev` + `npm start` 双进程 |

## 13.2 Docker Compose（db + redis + app）

```yaml
# docker-compose.yml（精简）
services:
  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: quickmark
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
    volumes: ["quickmark_mysql_data:/var/lib/mysql"]

  redis:
    image: redis:7-alpine

  app:
    build: .
    environment:
      USE_PRISMA: "1"
      DATABASE_URL: "mysql://root:${DB_PASSWORD}@db:3306/quickmark"
      JWT_SECRET: ${JWT_SECRET}
      REDIS_URL: "redis://redis:6379"
    depends_on: [db, redis]
    ports: ["3000:3000"]
    volumes:
      - ./prisma:/app/prisma      # 热重载 schema
      - ./server.js:/app/server.js
```

`utf8mb4` 必须显式指定，否则 MySQL 8 默认 `utf8mb4_0900_ai_ci`，emoji/生僻字可能存不进。`USE_PRISMA=1` 让 app 走 Prisma 路径。

## 13.3 当前生产架构（实测）

> 来源：2026-07 迁移到腾讯云轻量应用服务器（上海，Ubuntu 20.04，2核/2GB）。

- **MySQL / Redis**：跑在 Docker 容器（`quickmark-db` / `quickmark-redis`，`restart:always`）。数据卷 `quickmark_mysql_data` / `quickmark_uploads` 持久化。
- **应用**：宿主机 `node /home/ubuntu/quickmark/server.js`，由 **PM2** 守护（`pm2 start server.js --name quickmark`）。
- 项目目录 `/home/ubuntu/quickmark`，代码经自定义镜像从老服务器迁移。

**更新代码流程**（日常）：

```bash
# 本地
git push
# 服务器
ssh ubuntu@124.222.192.166
cd /home/ubuntu/quickmark
git pull
npm run build          # 产出前端 dist/
pm2 restart quickmark  # 必须 restart，build 才生效
```

注意：**docker-compose 里的 app 容器没在用**，应用是宿主机 PM2 跑的。别被 `docker ps` 里的 app 容器误导。

## 13.4 外网打不开？先看防火墙

最常见故障：本地 `curl /api/health` 返回 `{"status":"ok"}`，但外网访问超时。根因往往是**腾讯云轻量「防火墙」（安全组）没放行 TCP 3000**。

- 轻量防火墙在**腾讯云控制台**侧，实例内 `ufw`/`iptables` 看不到也改不了。
- 解决：控制台 → 防火墙 → 加一条「应用类型：自定义，协议 TCP，端口 3000，来源 0.0.0.0/0」。
- 应用本身监听 `0.0.0.0:3000`，端口没问题，只差防火墙这一步。

> ⚠️ 当前架构**未配 HTTPS**（裸 http :3000）。生产建议前方加 Nginx 反代 + Let's Encrypt，或换 https 域名。Cookie 的 `sameSite:lax` 在 https 下更安全。

## 13.5 环境变量（.env）

```
DB_PASSWORD=xxx            # 必填，否则启动失败
JWT_SECRET=至少32位随机串   # 必填，<32 字符启动失败
DATABASE_URL=mysql://...   # Prisma 用
REDIS_URL=redis://...
USE_PRISMA=1               # 1=Prisma 路径
SMTP_HOST/PORT/USER/PASS   # 找回密码用（QQ 邮箱）
```

`server.js` 启动期 `requireEnv('DB_PASSWORD')` 与 `requireJwtSecret()` 做 fail-fast——缺关键配置直接退出，而不是跑一半崩。

## 13.6 数据库迁移与备份

```bash
# 迁移（改了 schema 后）
npx prisma migrate dev        # 本地
# 或生产用 db push（无迁移历史时）
npx prisma db push

# 备份（生产务必先备再动）
docker exec -i quickmark-db mysql -u root -p$DB_PASSWORD quickmark > backup.sql
```

**血泪教训**：`prisma db push` 可能触发数据重置；操作前一定先 `mysqldump` 备份。曾因 DISCARD TABLESPACE 丢失 `.ibd` 文件，部分库只能从 binlog 恢复表结构、数据无法找回。

## 13.7 排错清单

| 现象 | 排查 |
|---|---|
| 外网超时，本地 OK | 腾讯云防火墙放行 3000 |
| 启动即退出 | 查 `DB_PASSWORD`/`JWT_SECRET` 是否配、是否 ≥32 位 |
| 笔记保存没反应 | 看 `USE_PRISMA` 与 `DATABASE_URL` 是否生效 |
| 图片 404 | `uploads/` 目录权限 + `/uploads` 静态挂载 |
| 搜索中文召回差 | 确认 MySQL 用 ngram FULLTEXT（见 knowledge/04） |

## 13.8 本篇知识点小结

- 三种形态：Docker / 宿主机 PM2 / 本地双进程。
- 生产 = Docker 跑 DB+Redis + 宿主机 Node+PM2 跑应用。
- 更新：`git pull → npm run build → pm2 restart`。
- 外网不通先查**云防火墙**（控制台侧），不是 iptables。
- 关键 env 缺失启动即失败（fail-fast）；改 schema 先备份再迁移。
- 当前未配 HTTPS，建议前置 Nginx+证书。
