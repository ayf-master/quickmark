# 06 · 三栏可拖拽布局

> 目标：理解 QuickMark 三栏（分类栏 / 列表 / 编辑器）宽度怎么用「纯函数」算出来，以及为什么不用 CSS `flex` 直接拖。

## 6.1 需求与坑

界面三栏：侧栏(Sidebar) | 列表(List) | 编辑区(Editor)。用户拖中间分隔条改宽度。直觉做法：拖谁谁变 `flex: 1`，相邻栏固定。但这样**拖列表分隔条会把「编辑区」挤小**，而用户预期是「列表变宽、侧栏不变」——因为 `flex-1` 是相对剩余空间，`flex` 容器里谁抢剩余空间不可控。

本项目的解法：**状态只存两栏宽度（sidebar/list），编辑区 = 视口总宽 − 前两栏 − 固定间隔**，宽度计算全部抽到纯函数 `src/utils/layout.js`，组件只调函数、不碰 DOM 布局细节。

## 6.2 纯函数：resizeSidebar / resizeList

```js
// src/utils/layout.js（精简）
export const MIN_SIDEBAR = 180;
export const MIN_LIST    = 220;
export const MIN_EDITOR = 320;
export const COLLAPSE_AT = 120;   // 拖到比这还窄 → 直接收起
export const EXPAND_DRAG = 36;    // 收起后再往外拖这么多 → 重新展开

// state: { sidebarWidth, listWidth, editorWidth }
export function resizeSidebar(state) {
  const total = window.innerWidth;
  let s = state.sidebarWidth;
  let l = state.listWidth;
  let e = state.editorWidth;

  if (s < COLLAPSE_AT) { s = 0; }                 // 收起侧栏
  else { s = Math.max(MIN_SIDEBAR, s); }

  // 维护「侧栏+列表」这一对的总宽不变（像 Blender 那样拖一个、另一个补）
  const pairMin = (s === 0 ? 0 : MIN_SIDEBAR) + MIN_LIST;
  if (l < MIN_LIST) {
    // 列表被压到最小 → 侵占侧栏（侧栏被「顶掉」）
    if (s > 0 && s + l < pairMin) s = Math.max(0, pairMin - l);
  }
  // 编辑区兜底
  e = Math.max(MIN_EDITOR, total - s - l);
  return { sidebarWidth: s, listWidth: l, editorWidth: e };
}
```

`resizeList` 对称。核心思想：**拖动只改变「被拖的那一栏 + 它的相邻栏」这一对的内部比例，编辑区只被动吃剩余空间**——符合「拖列表，侧栏不动」的直觉。

## 6.3 收起 / 重新展开

手机上空间小，拖到极窄应「收起」整栏（宽度 0），把空间全让给编辑区。`COLLAPSE_AT` 是收起阈值；收起后用户再往外拖超过 `EXPAND_DRAG` 才重新展开，避免「贴边抖动」反复收起/展开。

```js
if (s < COLLAPSE_AT) s = 0;   // 收起
// 重新展开在拖拽事件里判断：拖拽位移 > EXPAND_DRAG 且当前为 0 → 设为 MIN_SIDEBAR
```

## 6.4 组件怎么用

`App.vue` 把宽度写进 CSS 变量，分隔条 `pointermove` 时调纯函数：

```html
<div class="app-layout" :style="{
  '--sidebar-width': store.sidebarWidth + 'px',
  '--list-width': store.listWidth + 'px'
}">
  <Sidebar class="col-sidebar" />
  <LayoutResizer @drag="resizeSidebar(store.$state)" />
  <NoteList class="col-list" />
  <LayoutResizer @drag="resizeList(store.$state)" />
  <NoteEditor class="col-editor" />
</div>
```

```css
.col-sidebar { width: var(--sidebar-width); }
.col-list    { width: var(--list-width); }
.col-editor  { flex: 1; }   /* 编辑区吃剩余，纯函数已保证它 ≥ MIN_EDITOR */
```

宽度存 `localStorage`（store 里 `sidebarWidth/listWidth` 初始化时读），刷新后保持用户习惯。

## 6.5 为什么这个设计值得写进简历

- **关注点分离**：布局算术在纯函数里，可单测、可复用、不依赖 DOM。
- **可预测**：拖 A 只影响 A+B 一对，不连锁反应到 C。
- **响应式兜底**：`MIN_EDITOR` 保证编辑区永不被压没。
- **可测试**：`layout.test.js` 直接传 state 对象断言结果，不启浏览器。

## 6.6 本篇知识点小结

- 三栏宽度用 CSS 变量驱动，编辑区 `flex:1` 吃剩余。
- 宽度计算全在 `utils/layout.js` 纯函数，组件只调用。
- 「成对总宽守恒」：拖一栏、相邻栏补，符合直觉。
- 收起阈值 `COLLAPSE_AT` + 重展阈值 `EXPAND_DRAG` 防抖。
- localStorage 持久化用户偏好，纯函数 + Vitest 可单测。
