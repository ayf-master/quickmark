## 1.2 package.json 关键脚本

```jsonc
{
  "scripts": {
    "start":    "node server.js",          // 启动 Express 后端（:3000）
    "dev":      "vite",                     // 启动前端 dev server（:5173）
    "build":    "vite build",               // 产出 dist/
    "test":     "vitest run",              // 跑全部单测
    "test:pool":     "node test/pool.test.js",   // 原生池路径冒烟测试
    "test:prisma":   "node test/prisma.test.js", // Prisma 路径冒烟测试
    "prisma:generate": "prisma generate",
    "prisma:migrate":  "prisma migrate dev"
  },
  "engines": { "node": ">=20" }
}
```

开发时**前后端两个进程**：`npm run dev`（前端）在前台，`npm start`（后端）在另一个终端。Vite 把 `/api`、`/uploads` 代理到 :3000，前端代码里只写相对路径即可。

## 1.3 vite.config.js 三段关键配置

```js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import path from 'node:path';

export default defineConfig({
  resolve: {
    alias: {
      '@': path.resolve(__dirname, 'src'),     // import '@/store' → src/store
      '@/css': path.resolve(__dirname, 'css')
    }
  },
  server: {
    port: 5173,
    proxy: {
      '/api':     { target: 'http://localhost:3000', changeOrigin: true },
      '/uploads': { target: 'http://localhost:3000', changeOrigin: true }
    }
  },
  test: {
    environment: 'happy-dom',   // 轻量 DOM，跑组件/纯函数单测
    globals: true,
    include: ['src/**/*.test.js', 'test/unit/**']
  },
  build: { outDir: 'dist', emptyOutDir: false }
});
```

**要点**
- `@` 别名避免 `../../` 地狱，组件里统一用 `@/store`、`@/api`。
- dev proxy 让前后端「同源」开发，规避跨域 Cookie 问题（Cookie 是按域名+path 发的，同源才自动带）。
- `test.environment: 'happy-dom'`：Vitest 默认没有 DOM，happy-dom 提供 `document`/`window`，`layout.js` 这类用到 `window.innerWidth` 的单测才能跑。

> ⚠️ 沙箱/CI 注意：`node_modules/.bin/vite` 是 bash 启动脚本，不能直接 `node node_modules/.bin/vite`。要直接调用 `node_modules/vite/bin/vite.js build`。这是「vite build shim error」的根因。

## 1.4 Tailwind 与 CSS 变量

项目用 Tailwind 3.4 做原子类，但主题色走 CSS 变量（`css/` 下定义 `--bg-panel`、`--border-default`、`--bg-input` 等），支持亮/暗主题切换（`store.initTheme()` 切 `<html data-theme>`）。组件里混用：

```html
<div class="mode-switcher" :style="{ background: 'var(--bg-input)' }">
```

这样 Tailwind 管布局、CSS 变量管主题，互不打架。

## 1.5 测试怎么写（Vitest + happy-dom）

纯函数（如 `src/utils/layout.js`）最好测，不依赖 DOM：

```js
// src/utils/layout.test.js
import { describe, it, expect } from 'vitest';
import { resizeSidebar } from './layout.js';

describe('resizeSidebar', () => {
  it('抽屉宽度 < COLLAPSE_AT 时收起', () => {
    const s = { sidebarWidth: 100, listWidth: 400, editorWidth: 600 };
    const r = resizeSidebar(s);          // 100 < 120 → 收起 sidebar
    expect(r.sidebarWidth).toBe(0);
    expect(r.editorWidth).toBeGreaterThan(600); // 释放的空间给编辑区
  });
});
```

`layout.js` 用 `window.innerWidth` 当视口总宽，happy-dom 提供了它。这种「纯函数 + 单测」模式是本项目多处复用的工程范式（见 `knowledge/06`）。

## 1.6 本篇知识点小结

- 前端 Vite（:5173）+ 后端 Express（:3000）双进程，dev proxy 解决跨域。
- `@` 别名统一模块路径。
- 状态/工具尽量写成**纯函数**，配 Vitest + happy-dom 单测，可独立验证、易复现。
- 生产 `npm run build` → `dist/`，交给 Express 托管。
