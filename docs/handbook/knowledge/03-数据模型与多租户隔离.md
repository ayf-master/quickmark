# 03 · 数据模型与多租户隔离

> 目标：看懂 Prisma schema 的表结构，以及「每个用户只能看自己的数据」是怎么从数据库层就锁死的。

## 3.1 为什么用 Prisma（又保留原生池）

Prisma 提供类型安全的 schema 与迁移，但本项目同时保留了 `mysql2` 原生连接池作为另一条 DAL 路径（`USE_PRISMA=0` 本地/高频，`=1` 生产用 Prisma）。两条路最终都通过 `formatNote()` 映射成下划线命名字段，**上层路由不关心底层是谁**。

## 3.2 核心表（schema.prisma 精简）

```prisma
datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}

generator client { provider = "prisma-client-js" }

model User {
  id                  Int      @id @default(autoincrement())
  username            String   @unique
  email               String?  @unique
  passwordHash        String?
  passwordResetToken  String?
  passwordResetExpires DateTime?
  displayName         String?
  role                String   @default("user")
  isLocked            Boolean  @default(false)
  settings            Json?
  reviewStreak        Int      @default(0)
  lastReviewDate      DateTime?
  notes               Note[]
  categories          Category[]
}

model Category {
  id        Int      @id @default(autoincrement())
  name      String
  color     String?
  parentId  Int?
  userId    Int
  position  Int      @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  parent    Category?  @relation("CatTree", fields: [parentId], references: [id], onDelete: Cascade)
  children  Category[] @relation("CatTree")
  owner     User      @relation(fields: [userId], references: [id])
}

model Note {
  id          Int      @id @default(autoincrement())
  title       String
  content     String?
  isPinned    Boolean  @default(false)
  position    Int      @default(0)
  userId      Int
  mastery     Int?        // 间隔重复掌握度 0-5
  planData    Json?       // 计划甘特数据，不污染正文
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  owner       User        @relation(fields: [userId], references: [id])
  categories  NoteCategory[]
  reviewCards ReviewCard[]
}

model NoteCategory {
  noteId     Int
  categoryId Int
  note       Note     @relation(fields: [noteId], references: [id], onDelete: Cascade)
  category   Category @relation(fields: [categoryId], references: [id], onDelete: Cascade)
  @@id([noteId, categoryId])   // 联合主键，防重复关联
}

model ReviewCard {
  id        Int      @id @default(autoincrement())
  noteId    Int
  userId    Int
  dueDate   DateTime
  interval  Float    // 下次间隔（天）
  easeFactor Float   // SM-2 难度因子
  reps      Int       // 已复习次数
  note      Note     @relation(fields: [noteId], references: [id], onDelete: Cascade)
}

model Feedback {
  id        Int      @id @default(autoincrement())
  userId    Int
  content   String
  createdAt DateTime @default(now())
}
```

**关键设计**
- `relationMode = "foreignKeys"`：MySQL 用真实外键（而非 Prisma 默认的 `Prisma` 模式），保证 `onDelete: Cascade` 在数据库层生效（删分类 → 子分类/关联自动级联）。
- `NoteCategory` 联合主键 + 双向 `onDelete: Cascade`：删笔记或删分类，关联行自动清，不会留脏数据。
- `Category.parentId` 自引用 + `onDelete: Cascade`：删父分类，子分类一并删除（后端还有循环引用防护，见 `knowledge/12`）。
- `planData` / `mastery` 分离：计划与掌握度存结构化字段，正文保持纯 Markdown，干净可移植。

## 3.3 多租户隔离：从 DAL 第一参数锁死

**这是安全底座，也是面试高频点。** 每一个 DAL 函数第一个参数都是 `userId`，查询里强制 `where.userId = ?`：

```js
// prisma/dal.js（原生池路径示意）
async function listNotes(userId, { categoryId, search, pinned } = {}) {
  let sql = 'SELECT n.* FROM notes n WHERE n.user_id = ?';
  const params = [userId];
  if (categoryId) {
    sql += ` AND n.id IN (
      SELECT nc.note_id FROM note_categories nc WHERE nc.category_id = ?)`;
    params.push(categoryId);
  }
  if (search) { sql += ' AND (n.title LIKE ? OR n.content LIKE ?)'; params.push(`%${search}%`, `%${search}%`); }
  if (pinned)  { sql += ' AND n.is_pinned = 1'; }
  sql += ' ORDER BY n.position ASC, n.updated_at DESC';
  const [rows] = await pool.query(sql, params);
  return rows.map(formatNote);
}
```

即便用户伪造了别人的 `note_id`，因为 `user_id` 不匹配，结果也是空。**「属主校验」下沉到数据层，而不是只靠前端隐藏按钮**——这才是真正的隔离。

Prisma 路径同理，只是写法换成：

```js
prisma.note.findMany({ where: { userId, ... } });
```

## 3.4 字段映射：`formatNote`

数据库用下划线（`user_id`），前端用驼峰（`userId`）。`formatNote` 做唯一转换点：

```js
function formatNote(r) {
  return {
    id: r.id,
    title: r.title,
    content: r.content,
    isPinned: !!r.is_pinned,
    position: r.position,
    userId: r.user_id,
    categoryIds: [],          // 列表接口单独拼
    categoryNames: [],
    mastery: r.mastery ?? null,
    planData: typeof r.plan_data === 'string' ? JSON.parse(r.plan_data) : (r.plan_data || null),
    createdAt: r.created_at,
    updatedAt: r.updated_at
  };
}
```

**好处**：上层（路由/前端）永远看到一致的驼峰结构；哪天换数据库列名，只改这一处。

## 3.5 排序约定：收藏不置顶

注意 `ORDER BY n.position ASC, n.updated_at DESC`——**没有 `is_pinned`**。早期版本把收藏笔记 `ORDER BY is_pinned DESC` 置顶，用户反馈「收藏的反而打乱了手动顺序」。修复后收藏只作为筛选条件（`showPinnedOnly`），不再影响排序。详见 `knowledge/08`。

## 3.6 本篇知识点小结

- 表关系靠真实外键 + `onDelete: Cascade`，删父级自动清理子级与关联。
- `NoteCategory` 联合主键防重复关联。
- **多租户 = 每个 DAL 函数首参 `userId` + `where.userId`**，安全下沉到数据层。
- `formatNote` 统一下划线↔驼峰映射，上层解耦数据库细节。
- 收藏是「筛选」不是「置顶」，尊重手动排序。
