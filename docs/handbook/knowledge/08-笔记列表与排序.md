# 08 · 笔记列表与排序

> 目标：理解笔记列表怎么过滤、排序，以及「收藏为什么不再置顶」这个产品决策。

## 8.1 列表数据从哪来

列表展示的是 `store.filteredNotes`（一个 computed），不是原始 `store.notes`。它叠加了三层过滤：

```js
const filteredNotes = computed(() => {
  let list = store.notes;
  // 1) 当前分类筛选
  if (store.selectedCategoryId) {
    list = list.filter(n => (n.category_ids || []).includes(store.selectedCategoryId));
  }
  // 2) 仅看收藏
  if (store.showPinnedOnly) list = list.filter(n => n.is_pinned);
  // 3) 关键词搜索
  const q = store.searchQuery.trim().toLowerCase();
  if (q) list = list.filter(n =>
    (n.title || '').toLowerCase().includes(q) ||
    (n.content || '').toLowerCase().includes(q));
  return list;
});
```

注意：**筛选返回新数组，不修改 `store.notes`**。原始数据保持全量，切换分类只是换「视图」。

## 8.2 排序：尊重手动顺序，收藏不置顶

后端排序固定为：

```sql
ORDER BY n.position ASC, n.updated_at DESC
```

**没有 `is_pinned`**。这是一个刻意的修复：早期版本用 `ORDER BY is_pinned DESC, position ASC`，导致收藏的笔记全被顶到最前，打乱了用户拖出来的手动顺序。用户反馈后改为「收藏只是筛选条件（`showPinnedOnly`），不参与排序」。

`position` 字段的意义：用户在列表里**拖拽排序**时，后端 `PATCH /api/notes/reorder` 重写相关笔记的 `position`，前端按 `position` 升序展示，得到的就是用户安排的秩序。

## 8.3 新笔记插在哪

早期新笔记插在最前（position=0，其余 +1），用户觉得「应该出现在我正在看的位置附近」。修复后：

```js
// dal.createNote
const [max] = await pool.query('SELECT MAX(position) AS m FROM notes WHERE user_id = ?', [userId]);
const position = (max.m ?? 0) + 1;   // 新笔记排到当前用户列表末尾
```

新笔记落在新位置（列表底部），符合「先记下来、再整理」的直觉。列表组件里新笔记卡片高亮一下提示用户。

## 8.4 收藏切换

```js
togglePin() {
  if (!store.editingNote) return;
  const newPinned = !store.editingNote.is_pinned;
  store.editingNote.is_pinned = newPinned;
  API.updateNote(store.editingNote.id, { is_pinned: newPinned })
    .then(() => {
      const idx = store.notes.findIndex(n => n.id === store.editingNote.id);
      if (idx !== -1) store.notes[idx].is_pinned = newPinned;
    })
    .catch(() => { store.editingNote.is_pinned = !newPinned; });  // 失败回滚
}
```

注意 Prisma 里 `isPinned` 是 Boolean，**必须发 `true/false` 而非 `0/1`**，否则严格类型校验拒绝（这也是一个踩过的坑）。失败时在 `.catch` 里把本地状态回滚，保证 UI 与服务器一致。

## 8.5 点击卡片 → 打开（带跨分类兜底）

点列表项调 `store.openNote(note)`；若是「从 Wiki 链接跳到别的分类的笔记」，用 `openNoteFromElsewhere`：先把 `selectedCategoryId` 切到目标所属分类、清空搜索词，再 `loadNotes()` 把它拉进当前列表，最后 `openNote`——否则编辑器打开了、侧栏却看不到它，体验割裂。

## 8.6 本篇知识点小结

- 列表 = `filteredNotes` computed，三层过滤（分类 / 收藏 / 搜索）叠加，不改原数据。
- 排序 `ORDER BY position, updated_at`，**收藏不置顶**，尊重手动拖拽顺序。
- 新笔记 `position = MAX+1` 落底部。
- 收藏 `is_pinned` 发 Boolean；失败本地回滚。
- 跨分类跳转用 `openNoteFromElsewhere` 兜底，保证侧栏同步。
