# 05 · 认证与安全

> 目标：讲清「为什么用双 Cookie + CSRF 双提交」「bcrypt 怎么防拖库」「限流怎么挡爆破」。这是简历里最硬的安全知识点。

## 5.1 整体策略

| 威胁 | 防御 |
|---|---|
| XSS 偷 token | access token 放 **httpOnly Cookie**，JS 读不到 |
| CSRF 伪造请求 | 写操作带 **CSRF 双提交**（`qm_csrf` 可读 Cookie + 请求头比对） |
| 密码泄露 | **bcrypt** 单向哈希（含盐，慢哈希抗暴力） |
| 爆破登录 | **rate-limit**（登录 10 次/15 分钟） |
| 账号锁死 | 连续失败 `isLocked` 标记 |
| 弱密钥 | 启动期校验 `JWT_SECRET ≥ 32` 字符，否则 fail-fast |

## 5.2 bcrypt：为什么不用 MD5/SHA

```js
// prisma/auth.js
import bcrypt from 'bcryptjs';
const SALT_ROUNDS = 8;

export async function hashPassword(pwd) {
  return bcrypt.hash(pwd, SALT_ROUNDS);   // 自动加盐，输出 $2a$... 字符串
}
export async function verifyPassword(pwd, hash) {
  return bcrypt.compare(pwd, hash);        // 恒定时间比较，防时序攻击
}
```

**原理**：bcrypt 故意设计得「慢」（约 0.1s/次），且每次随机加盐。拖库后攻击者无法用彩虹表批量破解，逐个爆破成本极高。8 轮是安全与性能的平衡点。

## 5.3 JWT：双令牌 + 双 Cookie

```js
import jwt from 'jsonwebtoken';

export function signAccessToken(userId) {
  return jwt.sign({ uid: userId, type: 'access' },
    JWT_SECRET, { algorithm: 'HS256', expiresIn: '1h', issuer: 'quickmark', audience: 'qm-app' });
}
export function signRefreshToken(userId) {
  return jwt.sign({ uid: userId, type: 'refresh' },
    JWT_SECRET, { algorithm: 'HS256', expiresIn: '30d', issuer: 'quickmark', audience: 'qm-app' });
}

export function verifyToken(token) {
  // 显式声明算法，防「alg: none」降级攻击
  return jwt.verify(token, JWT_SECRET, { algorithms: ['HS256'], issuer: 'quickmark', audience: 'qm-app' });
}
```

**为什么 access 短、refresh 长？**
- access（1h）频繁使用，泄露窗口小；过期快。
- refresh（30d）只在 access 过期时用来换发，存 httpOnly Cookie，JS 拿不到。
- 即使 access 被盗，最多用 1 小时。

`setAuthCookies`：

```js
export function setAuthCookies(res, access, refresh) {
  res.cookie('qm_access',  access,  { httpOnly: true, sameSite: 'lax', maxAge: 3600_000 });
  res.cookie('qm_refresh', refresh, { httpOnly: true, sameSite: 'lax', maxAge: 30*24*3600_000 });
  // qm_csrf 可读，JS 能读它的值放进请求头做双提交
  res.cookie('qm_csrf', crypto.randomUUID(), { httpOnly: false, sameSite: 'lax', maxAge: 30*24*3600_000 });
}
```

`sameSite: 'lax'` 进一步限制第三方站带 Cookie，降低 CSRF 面。

## 5.4 CSRF 双提交校验

```js
export function csrfProtection(req, res, next) {
  // 只对写操作（非 GET/HEAD）校验
  if (req.method === 'GET' || req.method === 'HEAD') return next();
  const header = req.get('X-CSRF-Token');
  const cookie = req.cookies.qm_csrf;
  if (!header || !cookie) return res.status(403).json({ error: 'CSRF token missing' });
  // timingSafeEqual 防时序侧信道
  const a = Buffer.from(header), b = Buffer.from(cookie);
  if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) {
    return res.status(403).json({ error: 'CSRF token mismatch' });
  }
  next();
}
```

**为什么能防 CSRF？** 攻击者的恶意页面能「带」上 `qm_csrf` Cookie（浏览器自动发），但**读不到它的值**（httpOnly=false 仅对第一方能读），所以无法把它填进 `X-CSRF-Token` 头。值对不上 → 403。这就是「双重提交 Cookie」模式。

## 5.5 前端 authedFetch：自动带凭证 + 续期

```js
// src/api/index.js
function getCookie(name) {
  return document.cookie.split('; ').find(c => c.startsWith(name + '='))?.split('=')[1];
}

async function authedFetch(url, options = {}) {
  const isWrite = !['GET', 'HEAD'].includes((options.method || 'GET').toUpperCase());
  const headers = { ...options.headers };
  if (isWrite) headers['X-CSRF-Token'] = getCookie('qm_csrf') || '';
  let res = await fetch(url, { ...options, headers, credentials: 'include' });

  if (res.status === 401) {
    // 单飞续期：同一时刻只发一次 refresh，避免并发请求各自刷新
    if (!refreshing) { refreshing = tryRefresh(); }
    await refreshing; refreshing = null;
    res = await fetch(url, { ...options, headers, credentials: 'include' });
  }
  return res;
}
```

`credentials: 'include'` 让浏览器自动带 httpOnly Cookie；写操作补 CSRF 头。401 时单飞刷新，防并发反复刷新。

## 5.6 限流与锁号

```js
export const loginLimiter = rateLimit({
  windowMs: 15 * 60_000,   // 15 分钟
  max: 10,                 // 同一 IP 最多 10 次
  standardHeaders: true,
  legacyHeaders: false
});
// server.js: app.use('/api/auth/login', loginLimiter)
```

连续失败还会置 `User.isLocked`，需管理员/邮件解锁。全局还有 `100 次/分钟/IP` 兜底。

## 5.7 本篇知识点小结

- 密码用 bcrypt（慢哈希+盐），绝不存明文/MD5。
- 双令牌：access 短命 httpOnly，refresh 长命 httpOnly，降低泄露窗口。
- CSRF 双提交：`qm_csrf` 可读 Cookie + `X-CSRF-Token` 头，`timingSafeEqual` 比对。
- 前端 `credentials:'include'` 带 Cookie，写操作补 CSRF 头，401 单飞续期。
- rate-limit + isLocked 挡爆破；JWT_SECRET 弱则启动失败。
