后端：Node + Express + Prisma（兼 mysql2 原生池）+ MySQL8 + Redis7。
安全：JWT 双令牌 + CSRF 双提交 + bcrypt + rate-limit。
工程：Vitest + happy-dom 单测，Docker Compose 部署。

## 三、能讲清楚的 6 个亮点（面试高频）

1. **多租户隔离**（对应 03）：每个 DAL 函数首参 `userId` + `where.userId`，属主校验下沉到数据层，防越权。
2. **双数据访问层**（对应 04）：`USE_PRISMA` 切换 Prisma/原生池，返回统一 `formatNote` 结构，上层零改动。
3. **自动保存状态一致性**（对应 07）：`watch → 1s 防抖`，闭包快照 `noteId` 防串台；切笔记前 fire-and-forget 存旧笔记，修「丢修改」。
4. **CSRF 双提交**（对应 05）：httpOnly access/refresh Cookie + 可读 `qm_csrf` Cookie 与请求头 `timingSafeEqual` 比对。
5. **D3 知识图谱**（对应 11）：力模拟（斥力+引力+防叠）自动布局，`fx/fy` 钉住聚焦节点，聚焦/邻居高亮。
6. **可拖拽三栏布局**（对应 06）：宽度计算抽成纯函数（成对总宽守恒），可单测、不连锁影响编辑区。

## 四、面试可能追问 & 应答要点

**Q：为什么不用 Pinia？**
A：项目规模下 `reactive()` 单例已够，本质是手写迷你 Pinia；减少样板，且全应用共享同一份响应式状态。

**Q：JWT 为什么分 access/refresh？**
A：access 短命（1h）降低泄露窗口，refresh 长命（30d）仅用于续期且 httpOnly，即使 access 被盗最多用 1 小时。

**Q：CSRF 双提交为什么安全？**
A：攻击者能带 Cookie 但读不到 `qm_csrf` 值（仅第一方可读），无法填进请求头，值对不上被拒。

**Q：自动保存怎么防「切笔记丢内容」？**
A：切换前 fire-and-forget 同步存旧笔记 + cancelAutoSave；异步写库前先快照 id/标题/分类，防 `await` 后状态串台。

**Q：D3 力导向是什么？**
A：物理模拟：节点互斥（forceManyBody）、边像弹簧（forceLink）、防重叠（forceCollide），平衡后自然聚簇；`tick(30)` 预热让图打开即稳。

**Q：收藏为什么不置顶？**
A：早期置顶打乱了用户手动顺序，改为「收藏只作筛选条件，排序仍按 position」，尊重用户整理的秩序（对应 08）。

**Q：图片标注怎么导出？**
A：Canvas `toBlob` 出 PNG → 上传 → 父组件把笔记里旧图 URL 整体替换成新 URL，原地更新不破坏结构（对应 09）。
