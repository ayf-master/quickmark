# 07 · 核心算法：SM-2 间隔重复（Anki 同款）

> 间隔重复是这个项目最有"算法含量"的功能：基于遗忘曲线，
> 把每次复习的难度反馈转化为下一次复习的时间安排。
> 读完本文你应能：在纸上推导间隔序列、解释 EF 公式、讲清纯函数设计。

---

## 1. 背景：艾宾浩斯遗忘曲线

人类记忆会随时间衰减：

```
记忆保持率
  100% ┤██
       ┤███
       ┤████
       ┤█████
       ┤██████       ┌────────── 如果每次在遗忘前复习
       ┤███████      │            记忆强度会越来越高
       ┤████████     │
       ┤█████████    │
       ─────────────────────────── 时间
```

**核心洞察**：与其固定周期复习，不如**每次复习后根据掌握程度动态调整下次间隔**——这就是 SM-2 算法（SuperMemo 第二代，1987 年论文）。

---

## 2. 三个状态变量（复习卡上存什么）

```prisma
model ReviewCard {
  dueDate    DateTime  // 下次该复习的日期
  interval   Int       // 当前间隔（天）
  easeFactor Float     // 难度系数 EF（记忆牢固程度）
  reps       Int       // 连续答对次数
}
```

| 变量 | 含义 | 初始值 | 范围 |
|------|------|--------|------|
| `dueDate` | 到期日 | 今天 | - |
| `interval` | 两次复习间隔天数 | 0 | 1, 6, 15, 30... |
| `easeFactor` | 难度系数，越高越好记 | 2.5 | 下限 1.3 |
| `reps` | 连续成功的次数 | 0 | 0,1,2,... |

## 3. 算法核心（prisma/sm2.js —— 全项目最短却最精华的文件）

```js
const MIN_EF = 1.3;

function gradeCard(card, quality) {
  let { easeFactor, interval, reps } = card;

  // 失败（quality < 3）：重置进度，明天再练（EF 保留——难度记忆不丢）
  if (quality < 3) {
    return { easeFactor, interval: 1, reps: 0, dueInDays: 1 };
  }

  // 成功：按连续成功次数推下一次间隔
  if (reps === 0) {      // 第 1 次成功 → 1 天后
    interval = 1;
  } else if (reps === 1) {  // 第 2 次成功 → 6 天后
    interval = 6;
  } else {               // 之后：间隔 × 难度系数（指数增长）
    interval = Math.round(interval * easeFactor);
  }
  reps += 1;

  // 更新难度系数 EF（SM-2 论文公式）
  easeFactor += 0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02);
  if (easeFactor < MIN_EF) easeFactor = MIN_EF;

  return { easeFactor, interval, reps, dueInDays: interval };
}
```

### 3.1 间隔序列推导（面试手推）

假设一路都答"记得"（quality=4，EF 稳定 2.5）：

```
第 1 次复习：reps=0 → interval = 1 天
第 2 次复习：reps=1 → interval = 6 天
第 3 次复习：reps=2 → interval = 6 × 2.5 = 15 天
第 4 次复习：reps=3 → interval = 15 × 2.5 = 38 天
第 5 次复习：reps=4 → interval = 38 × 2.5 = 94 天
...

1 → 6 → 15 → 38 → 94 → ... （指数增长）
```

**这就是 Anki 的复习节奏**：越熟练的卡片出现得越少。

### 3.2 失败的处理（面试追问）

```
答错（quality=2）：interval=1, reps=0，明天再练
  但 EF 不变 → 卡片回到起点，但难度记忆保留
```

**设计思想**：失败不惩罚"难度"，只重置"节奏"——符合"今天忘了 ≠ 永远难记"。

### 3.3 EF 更新公式拆解

```js
easeFactor += 0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02);
```

代入不同评分（quality 0-5）：

| quality | 含义 | ΔEF |
|---------|------|-----|
| 5 | Easy 太简单 | +0.10 |
| 4 | Good 记得 | 0（不变） |
| 3 | Hard 有点难 | -0.14 |
| 2 | Fail 忘了 | -0.32 |

**机制**：越难 → EF 降越多 → 后续间隔增长越慢 → 复习更频繁。自适应的关键。

## 4. 业务逻辑层（prisma/review.js）—— 算法怎么接入系统

### 4.1 注册（enroll）：创建复习卡

```js
async function enrollNote(userId, noteId, prisma) {
  // 一篇笔记一张卡，重复注册忽略
  const card = await prisma.reviewCard.create({
    data: { noteId, userId, dueDate: new Date() }   // 初始：今天到期
  });
}
```

### 4.2 到期查询（getDueNotes）：今日该复习的

```js
const cards = await prisma.reviewCard.findMany({
  where: { userId, dueDate: { lte: endOfToday() } },  // dueDate <= 今天 23:59:59
  include: { note: { select: { id: true, title: true } } }
});
```

走复合索引 `[userId, dueDate]`，高频查询性能有保证。

### 4.3 标记复习（markReviewed）：调用算法 + 更新三处

```js
async function markReviewed(userId, cardId, prisma) {
  // 1. 调 SM-2 纯函数（quality=4 固定"记得"）
  const res = gradeCard(
    { easeFactor: card.easeFactor, interval: card.interval, reps: card.reps },
    4
  );
  // 2. 计算下次到期日
  const due = new Date();
  due.setDate(due.getDate() + res.dueInDays);
  // 3. 更新卡片 + 笔记掌握度 + 连续打卡
  await prisma.reviewCard.update({ where: { id: cid }, data: { ...res, dueDate: due } });
}
```

### 4.4 掌握度（mastery 0-5）—— 衍生指标

```js
const mastery = Math.max(0, Math.min(5, res.reps + (res.interval >= 15 ? 1 : 0)));
```

- reps 越高越熟；间隔 ≥15 天（≈第 3 次成功）额外 +1
- 驱动知识图谱着色（功能联动）

### 4.5 连续打卡（streak）

```js
// 昨天复习过 → +1；隔天断 → 重置 1
streak = prev === yStr ? streak + 1 : 1;
```

## 5. 为什么 SM-2 写成"纯函数"？（架构品味）

```js
// sm2.js：输入卡片状态 + 评分 → 输出新状态。不碰数据库、不依赖外部。
function gradeCard(card, quality) { ... }
module.exports = { gradeCard, MIN_EF };
```

**纯函数** = 相同输入永远相同输出 + 无副作用（不读写外部状态）。

好处：
1. **可单测**（test/sm2.test.js 存在）：不用数据库就能测算法正确性
2. **可复用**：前端也能 import（理论上）
3. **心智简单**：数据进、数据出，推理零负担

**面试话术**："算法我抽成纯函数模块，与业务层分离——数据库操作放 review.js，算法放 sm2.js，配合单元测试，改算法不影响业务，测业务不依赖数据库。这是分层与可测试性的实践。"

## 6. 与 Anki 的对比（体现研究深度）

| 维度 | Anki | 本项目 |
|------|------|--------|
| 算法 | SM-2 变体（FSRS 新版） | 原始 SM-2 |
| 卡片粒度 | 卡片/笔记 | 一篇笔记一张卡 |
| 评分 | 4 档（Again/Hard/Good/Easy） | 简化：quality=4 固定 |
| 失败处理 | 有重学流程 | 重置为 1 天 |

**诚实说明**："Anki 的完整流程有复习/学习/重学三状态和 FSRS 预测，我实现的是 SM-2 核心——间隔调度 + EF 自适应，对产品场景足够。"

## 7. 前端联动（怎么让用户感知）

```
后端 getDueNotes → 返回到期卡片列表
  └─▶ store/features.js 的 dueNoteIds 共享状态
       └─▶ NoteList.vue：到期笔记卡片蓝色高亮 + 到期徽章
            └─▶ 点击"标记已复习" → API.markReviewed(cardId)
                 └─▶ removeDueNote(id) → 高亮立即消失（不用刷新页面）
```

**体验设计点**：标记后立即从高亮队列移除——反馈即时性（本项目专门修过这个问题）。
