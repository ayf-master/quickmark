# 08 · 核心功能：甘特图实现原理

> 甘特图是本项目最复杂的前端功能，也是简历上最有画面感的亮点。
> 读完本文你应能讲清楚：日期→坐标的换算、CSS 定位渲染、拖拽调度的交互设计。

---

## 1. 功能概览（用户视角）

- 给笔记设定"起止日期 + 进度 + 颜色"（编辑器里 📅 按钮）
- 甘特图里笔记变成"任务条"，按分类分组排列
- 三种缩放级别：周（44px/天）、月（22px/天）、年（10px/天）
- 交互：拖拽条左/右边缘改起止日期、拖条身平移、拖 ⠿ 手柄换行排序、点击条打开笔记
- 今天红色竖线标记

## 2. 数据模型：计划存哪里？

**用户不想要"计划数据污染笔记正文"**——这是个产品决策：


## 3. 核心数学：日期 → 像素坐标

甘特图渲染的本质：**把日期换算成水平像素位置**。

### 3.1 三个工具函数

```js
// 日期差（含头不含尾）→ 决定条的长度
export function daysBetween(a, b) {
  const ta = new Date(a.getFullYear(), a.getMonth(), a.getDate());
  const tb = new Date(b.getFullYear(), b.getMonth(), b.getDate());
  return Math.round((tb - ta) / 86400000);   // 86400000 = 24h 的毫秒数
}

// Date → 'YYYY-MM-DD'（本地时区安全）
export function fmtDate(d) { ... }

// 'YYYY-MM-DD' → Date
export function parseDate(str) {
  const [y, m, d] = str.split('-').map(Number);
  return new Date(y, m - 1, d);   // 注意：月份 0 起
}
```

**⚠️ 日期换算的坑（本项目踩过）**：
- 用 `new Date('2026-08-01')` 解析字符串在部分时区会差 8 小时（UTC 时区偏移）
- 正确做法：**手动 split 成数字构造**，保证本地时区
- 天数差必须"清零时分秒"再算，否则 23:59 vs 00:01 会差一天

### 3.2 位置计算（GanttChart.vue 核心）

```js
// 每个视图的"每像素对应多少天"
const dayW = computed(() => zoom.value === 'week' ? 44 : zoom.value === 'month' ? 22 : 10);

// 条的位置：从起点到今天的天数 × 每像素
function barStyle(plan) {
  const start = parseDate(plan.start);
  const end = parseDate(plan.end);
  const left = daysBetween(viewportStart, start) * dayW.value;  // 距左边
  const width = daysBetween(start, end) * dayW.value;           // 条宽
  return { left: left + 'px', width: width + 'px' };
}
```

**本质**：甘特图 = 一个时间轴 × 行（泳道）的二维网格，每个任务条就是网格上的一个绝对定位矩形。

```
时间轴:  ────|────────|────────|────────|────▶
            8/1      8/5      8/10     8/15
              ██████████████← 条: left=0px, width=14天×44px
```

甘特图不能无限宽——需要"时间窗口"：

## 4. 渲染架构（关键 CSS 技术）

### 4.1 绝对定位 + 百分比/像素

```html
<div class="gantt-body">                  <!-- 相对定位容器 -->
  <div class="today-line" :style="{ left: todayLeft + 'px' }" />  <!-- 今天红线 -->
  <div v-for="(note, i) in groupedNotes" :key="note.id"
       class="task-row">                  <!-- 泳道 -->
    <div class="task-bar"
         :style="barStyle(getPlan(note))">  <!-- 任务条 -->
      {{ note.title }}
    </div>
  </div>
</div>
```

### 4.2 为什么不用 Canvas/SVG？（面试可讲）

| 方案 | 优点 | 缺点 | 本项目选择 |
|------|------|------|-----------|
| CSS 绝对定位 | 简单、事件天然（DOM）、样式易调 | 节点多时性能下降 | ✅ |
| SVG | 矢量、可缩放 | 事件绑定繁琐 | |
| Canvas | 性能最好 | 无事件、需手写命中检测 | |

**判断标准**：任务条数量 = 笔记数量（几十~几百），CSS 完全扛得住；交互（拖拽、点击、hover）用 DOM 事件最自然。

### 4.3 多级缩放（周/月/年）

```js
const dayW = zoom === 'week' ? 44 : zoom === 'month' ? 22 : 10;
```

三个视图共用同一套计算，只是 `dayW` 不同：
- 周视图：1 天 44px，看近一周细节
- 月视图：1 天 22px，一个月约 660px
- 年视图：1 天 10px，12 个月约 3650px（横向滚动）

**头部时间刻度**：周/月视图显示"星期 + 月/日"，年视图显示"月份"（宽度 = 当月天数 × dayW），居中显示。

## 5. 交互设计（本项目最复杂的部分）

### 5.1 拖拽调整日期（三区域手柄）

任务条分三个可拖区域：

```
      ← 缩左    ←─ 平移 ─→   缩右 →
┌────────┬────────────────────┬────────┐
│ handle │      bar body      │ handle │
└────────┴────────────────────┴────────┘
```

用 mousedown + mousemove + mouseup 实现（原生 JS，不引库）：

```js
function onMouseDown(e, note, zone) {
  const startX = e.clientX;
  const origStart = parseDate(plan.start);
  // 记录鼠标偏移，mousemove 时换算成天数增量
  function onMove(ev) {
    const dx = ev.clientX - startX;            // 像素差
    const days = Math.round(dx / dayW.value);  // → 天数
    // zone === 'left'  → start 加 days（宽度变化）
    // zone === 'body'  → start/end 同时加 days（整体平移）
    // zone === 'right' → end 加 days
    updatePlan(note, newPlan);                  // 实时更新（防抖存后端）
  }
  document.addEventListener('mousemove', onMove);
  document.addEventListener('mouseup', onUp, { once: true });
}
```

**像素 → 天数的核心换算**：`days = Math.round(dx / dayW)`——所有拖拽都是这行代码的变体。

### 5.2 拖拽排序（HTML5 drag & drop）

任务条带一个 ⠿ 手柄（drag handle），用 HTML5 DnD：

```js
// 关键坑（本项目修过）：dragover 高频触发，每次都重排数组会 DOM 抖动
// 解决：lastOverId 守卫——只有目标变化才重排
let lastOverId = null;
function onDragOver(e, target) {
  e.preventDefault();
  if (target.id === lastOverId) return;   // 高频过滤
  lastOverId = target.id;
  reorderNotes(target.id);                // 真正重排一次
}
```

**面试亮点**："拖拽排序的高频事件我做了一致性守卫（只在目标变化时重排），避免了 DOM 抖动——这是 HTML5 DnD 的经典性能陷阱。"

### 5.3 交互反馈

- 拖拽中：条半透明 + 阴影（视觉反馈）
- 点条：打开对应笔记编辑器
- 进度：条内白色半透明进度条（宽度 = progress%）

## 6. 编辑器的计划面板联动

```
NoteEditor.vue 点 📅
  └─▶ 弹出面板：起止日期 picker + 进度滑块 + 颜色色板
       └─▶ watch(store.editPlanData) 双向同步
            └─▶ 点"确定" → confirmPlan()
                 └─▶ store.saveCurrentNote() → PUT /api/notes/:id（planData 一起保存）
```

**数据流关键**：编辑面板的本地 ref ↔ store.editPlanData 用 watch 同步，关闭面板后重开重新从 store 拉取——保证"取消"不残留脏数据。

## 7. 踩过的坑（面试讲这些 = 真实经验）

| 坑 | 现象 | 修复 |
|----|------|------|
| 时区偏移 | 日期差 1 天 | parseDate 手动 split 构造 |
| ES6 简写错误 | `month,` 应为 `month: m`，字段变 undefined | 修正简写 |
| JSON.parse 崩溃 | planData 格式异常整个应用挂 | getPlan 包 try-catch |
| 修改 props | @keydown.escape 直接改 visible prop 报错 | 改为 emit('close') |
| dragover 抖动 | 拖拽排序 DOM 狂闪 | lastOverId 守卫 |
| 到期徽章重叠 | 右上角徽章压删除按钮 | 移到右下角 |
