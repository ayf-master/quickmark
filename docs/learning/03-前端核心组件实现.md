## 2. 手写全局 Store（不用 Pinia 的设计）

项目早期没有引入 Pinia，自己实现了一个轻量状态容器，核心就 20 行：

```js
// 简化版实现原理
let instance = null;

function createStore() {
  const state = reactive({ ... });   // Vue 响应式对象，全局唯一
  return {
    state,
    openNote(note) { state.currentNote = note; },
    closeEditor() { state.currentNote = null; }
  };
}

export function useStore() {
  if (!instance) instance = createStore();   // 单例：全局只有一份
  return instance;
}
```

**核心概念：单例 + 响应式。**
- 单例：所有组件拿到的是**同一个** store 对象
- 响应式：任何组件改了 store 里的数据，所有使用它的组件自动更新

### Store 里有什么（src/store/index.js）

| 状态 | 作用 |
|------|------|
| `notes` / `categories` | 笔记列表、分类树 |
| `currentNote` / `editPlanData` | 正在编辑的笔记、计划数据 |
| `showEditor` | 编辑器开关 |
| `loading` | 全局加载状态 |

### 关键方法调用链（"打开一篇笔记"）

```
NoteList.vue
  点击笔记卡片
    └─▶ store.openNote(note)        # 设置 currentNote + 拉详情
          └─▶ store.saveCurrentNote() # 保存时调 API.updateNote(id, data)
                └─▶ api/index.js      # fetch PUT /api/notes/:id
                      └─▶ 后端更新数据库
```

**面试点**：手写 store 展现了理解"状态管理本质 = 共享响应式数据"而非只会调库。

## 3. API 封装层（src/api/index.js）—— 前端最有讲究的文件

所有网络请求都封装在这一个文件里，统一处理三件事：

### 3.1 自动带 Cookie（credentials: 'include'）

```js
const opts = { credentials: 'include', ...options };
```

浏览器默认**不跨域携带 Cookie**，这里显式声明，登录态才能带上。

### 3.2 写操作自动加 CSRF 头

```js
const method = (opts.method || 'GET').toUpperCase();
if (method !== 'GET' && method !== 'HEAD') {
  const csrf = readCsrfCookie();          // 从 qm_csrf cookie 读取
  if (csrf) opts.headers['X-CSRF-Token'] = csrf;
}
```

这是与后端 CSRF 防护配合的关键：**cookie 里的 CSRF token 和请求头里的必须一致**，攻击者（跨站请求）读不到 cookie 值就过不了校验。

### 3.3 401 自动刷新 Token（单飞模式）

```js
let refreshPromise = null;  // 单飞：多个并发 401 只触发一次 refresh

if (resp.status === 401 && !url.includes('/api/auth/')) {
  const refreshed = await tryRefresh();   // POST /api/auth/refresh
  if (refreshed) resp = await fetch(url, opts);  // 重发原请求
}
```

**面试亮点**：
- "单飞"（single-flight）：并发请求同时 401 时，只发一次 refresh 请求，避免 token 刷新风暴
- 用户无感续期：access token 1h 过期，refresh token 30d，过期后自动续期，体验像"永远在线"

## 4. 功能开关体系（featureManifest + features store）

这是本项目最有特色的架构设计：**用户可配置的功能面板**。

### 4.1 清单式注册（src/featureManifest.js）

```js
export const featuresManifest = [
  { id: 'spacedRepetition', title: '间隔重复', available: true, hasBadge: true },
  { id: 'canvas', title: '2D 画布', available: true, component: canvasBoard },
  { id: 'ganttChart', title: '计划甘特表', available: true }
];
```

每个功能是一条**元数据**：id、名称、描述、组件。新增一个功能 = 加一行。

### 4.2 状态流转

```
用户点齿轮 → FeaturePanel.vue 开关
  └─▶ features.toggle('ganttChart')        # 前端内存立即生效（400ms 防抖）
        └─▶ API.updateSettings({features}) # 持久化到 User.settings JSON
```

### 4.3 后端白名单校验（prisma/settings.js）

```js
const KNOWN_FEATURES = ['spacedRepetition', 'canvas', 'ganttChart'];

// 未知键直接丢弃，防脏数据
for (const k of KNOWN_FEATURES) {
  if (typeof obj.features[k] === 'boolean') features[k] = obj.features[k];
}
```

**面试话术**："功能开关用清单式注册 + 后端白名单，前端加功能只改 manifest，后端只认白名单键——扩展性和安全性都有了。"

## 5. 关键组件逐个看

### 5.1 NoteList.vue —— 笔记列表

- `v-for` 渲染卡片，`v-if` 处理空状态
- 到期笔记高亮：读取共享的 `dueNoteIds`，有则加 `.due` class（蓝色高亮）
- 点击卡片 → `store.openNote(note)` → 打开编辑器

### 5.2 NoteEditor.vue —— 编辑器（最复杂组件）

一个文件里包含：标题输入、内容编辑（markdown-it 渲染）、分类选择、置顶开关、**计划设置（📅）**、删除/保存。

**计划设置流程（本项目核心交互）：**
```
点 📅 按钮 → 弹出面板（起止日期/进度滑块/颜色）
  → watch 同步 store.editPlanData
  → 点"确定" → confirmPlan() → store.saveCurrentNote() 立即保存到后端
```

关键设计：计划数据存在 `note.planData`（数据库 JSON 字段），**不污染笔记正文**——这是用户明确要求的（"这是用户写笔记的地方"）。

### 5.3 NoteCard.vue —— 单卡片

- 显示标题、分类、到期徽章（右下角，避让删除按钮）
- 置顶标记、拖拽排序（HTML5 drag & drop）
- 到期卡片蓝色高亮

### 5.4 LoginView.vue —— 登录/注册/找回密码

三模态切换：`mode = 'login' | 'register' | 'forgot'`，watch 切换时清空表单。

**找回密码流程（验证码版）：**
```
步骤 1: 输入邮箱 → POST /api/auth/forgot-password
步骤 2: 后端生成 6 位验证码 → 发邮件 → 存 SHA-256 哈希
步骤 3: 输入验证码 + 新密码 → POST /api/auth/reset-password
步骤 4: 后端校验哈希 + 过期时间 → 改密码 → 清理验证码
```

### 5.5 AppHeader.vue —— 导航入口

- 功能按钮（甘特图 📊、间隔重复 📝）通过 watch 与 features 开关同步
- 功能未开启时不显示（或提示开启）

## 6. 组件间协作全景（一次完整用户旅程）

```
用户打开网站
  → LoginView 登录 → emit('success') → App.vue 切换主界面
  → NoteList onMounted 拉笔记 + 分类
  → 用户点齿轮开启"间隔重复"
      → FeaturePanel 调 API → 后端存 settings
  → NoteList 拉到期笔记 → 到期卡片蓝色高亮
  → 用户打开笔记 → NoteEditor
  → 用户点 📅 设计划 → confirmPlan → 存 planData
  → 用户点 📊 打开甘特图 → GanttChart 读所有 notes.planData → 渲染任务条
```

## 7. 面试高频追问

| 问题 | 答案 |
|------|------|
| 为什么不用 Pinia/Vuex？ | 早期手写 store 满足需求；核心是共享响应式单例，后期可平滑迁移 |
| 前端怎么防 CSRF？ | 见 06 文档：double-submit cookie + SameSite=Lax |
| 401 自动刷新怎么实现？ | 拦截响应，单飞刷新，重发原请求（3.3 节） |
| 功能开关怎么加新功能？ | manifest 加一行 + 后端白名单加一个键（4 节） |
| 到期高亮怎么实时更新？ | 共享 store 的 dueNoteIds，标记已复习后调 removeDueNote 立即生效（不用刷新） |
