## 1. 简历项目描述（直接抄/微调）

### 版本 A：偏后端

```
QuickMark · 多用户笔记应用（全栈）
技术栈：Vue 3 + Express + Prisma + MySQL + Redis + Docker

- 独立设计并实现基于 SM-2 算法的间隔重复复习系统（Anki 同款调度），
  实现 interval/EF 自适应调度与连续打卡统计，算法抽离为纯函数并配套单元测试

  支持笔记维度的时间规划与进度管理
- 实现完整 JWT 认证体系：access(1h)/refresh(30d) 双 token + 轮换机制、
  httpOnly Cookie + double-submit CSRF 防护、bcrypt 加盐哈希、
  找回密码邮箱验证码（SHA-256 哈希存储 + 5 分钟过期 + 防枚举）
- 使用 Prisma ORM 完成 6 张表设计（多级分类树、多对多关联、JSON 扩展字段），
  通过 ngram 解析器实现中文全文搜索
- 混合部署：MySQL/Redis 容器化（数据卷持久化）+ PM2 进程守护，
  编写自动化部署流程与健康检查
```

### 版本 B：偏前端

```
QuickMark · 多用户笔记应用（全栈）
技术栈：Vue 3 + Vite + Express + MySQL + Docker

- 基于 Vue 3 组合式 API 构建 SPA：手写全局状态管理（响应式单例）、
  API 封装层（401 单飞自动刷新 + CSRF 头自动注入）
- 实现计划甘特图组件：日期→像素坐标换算、三级缩放、原生拖拽交互
  （边缘调日期/平移/排序），用 lastOverId 守卫解决 dragover 高频重排性能问题
- 实现用户功能开关体系：清单式注册（featureManifest）+ 后端白名单校验，
  支持间隔重复/画布/甘特图按用户独立开关
- 实现到期笔记实时高亮与"标记已复习"即时反馈（共享状态驱动）
```

### 简历写法要点

1. **动词开头 + 量化**："实现""设计""优化"，不要"参与""协助"
2. **一条一个亮点**：算法/安全/性能/部署，每个点独立成行
3. **别写"熟悉 Vue"这种空话**，写"实现了什么、怎么实现的"
4. 项目名 + 在线地址（http://124.222.192.166:3000）+ GitHub 链接

## 4. STAR 讲项目框架（任何追问都套用）

```
S（情境）：为什么做这个功能 / 遇到什么问题
T（任务）：要实现什么目标
A（行动）：怎么做的，做了什么技术决策，为什么
R（结果）：效果如何，学到了什么
```

**示例（SM-2 算法）：**
> S：笔记记完就忘，需要提醒复习
> T：实现"到期提醒 + 自适应复习节奏"
> A：调研后发现 Anki 的 SM-2 算法最成熟——间隔指数增长 + 难度自适应。
> 我把它抽成纯函数模块（输入卡状态+评分，输出新状态），配套单元测试，
> 数据库只存三个状态变量（interval/EF/reps）
> R：到期笔记自动高亮，间隔从 1→6→15→38 天指数增长，记忆效率显著提升

**示例（CSRF 防护）：**
> S：Cookie 自动携带导致跨站请求伪造风险
> T：在不用第三方框架的情况下实现 OWASP 级防护
> A：选 double-submit cookie 模式（cookie 值 + 请求头值必须一致），
> 配合 SameSite=Lax 双保险，比较用 timingSafeEqual 防时序攻击
> R：写操作全被保护，安全设计完整（helmet + 三层限流 + bcrypt 全覆盖）

## 5. 被问到"这是 AI 写的吧？"怎么办

诚实 + 展示深度：

> "这个项目是我主导设计、AI 辅助编码完成的。我会手写核心逻辑，
> 比如 SM-2 算法、CSRF 防护、甘特图的坐标换算，这些我都理解原理。
> 我更想强调的是设计和排查能力：比如我解决过 Docker 容器里 Node
> require 缓存不更新的问题，也处理过时区导致日期差一天的问题。"

**要点**：AI 是工具，你掌握的是**决策权**——为什么这么设计、出问题怎么排。
