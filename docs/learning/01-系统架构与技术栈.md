# 01 · 系统架构与技术栈

> 面试官第一个问题通常是："介绍一下你这个项目的架构。"
> 读完本文，你应该能画出一张架构图并解释每一层的职责。

## 1. 总体架构图

```
┌─────────────────────────────────────────────────────┐
│                     用户浏览器                        │
│            Vue 3 SPA (单页应用)                      │
│   LoginView / NoteList / NoteEditor / GanttChart     │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP (fetch + Cookie)
                       ▼
┌─────────────────────────────────────────────────────┐
│              Express 应用 (Node.js)                  │
│  ┌──────────┬──────────┬──────────┬──────────────┐  │
│  │ helmet   │ 请求日志  │ 鉴权中间件 │ CSRF 防护    │  │
│  │ 安全头   │ 中间件    │ attachUser│ requireAuth  │  │
│  └──────────┴──────────┴──────────┴──────────────┘  │
│  ┌──────────────────────────────────────────────┐   │
│  │ 路由层: /api/auth /api/notes /api/categories  │   │
│  │        /api/review /api/settings /api/upload  │   │
│  └──────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────┐   │
│  │ 业务层: dal.js(数据访问) review.js(复习)       │   │
│  │         settings.js(开关) email.js(邮件)      │   │
│  └──────────────────────────────────────────────┘   │
└───────┬────────────────────────┬────────────────────┘
        │ Prisma ORM              │ ioredis
        ▼                         ▼
┌──────────────┐          ┌──────────────┐
│   MySQL 8    │          │   Redis 7    │
│  数据持久化   │          │  缓存/限流    │
└──────────────┘          └──────────────┘
```

**核心设计思路：分层。** 每一层只做自己的事，通过接口通信：

| 层 | 职责 | 类比 |
|----|------|------|
| 前端 (Vue) | 渲染界面、收集用户输入 | 餐厅前台 |
| 路由层 (Express Router) | 接收请求、校验参数、返回响应 | 传菜员 |
| 业务层 (dal/review) | 核心逻辑、数据组装 | 厨师 |
| 数据层 (Prisma/MySQL) | 存储、查询 | 仓库 |

## 2. 技术栈选型理由（面试必答）

### 2.1 为什么前端用 Vue 3 而不是 React？

- **组合式 API（Composition API）**：把相关的逻辑（数据 + 方法）写在一起，代码组织更清晰。相比 React 的 Hooks，心智负担更小
- 响应式是 Vue 的强项：数据一变，界面自动更新，不需要手动操作 DOM
- 本项目规模是中小型 SPA，Vue 的模板语法 + 单文件组件（.vue）开发效率最高
- 生态：Vite 构建工具极快（毫秒级热更新）

### 2.2 为什么后端用 Node.js + Express？

- 前后端**同一门语言（JavaScript）**，降低全栈开发的心智成本
- Express 是 Node 最成熟的 Web 框架：中间件机制灵活，生态丰富
- 本项目是 I/O 密集型（数据库查询、文件上传）而非 CPU 密集型，Node 的事件驱动模型非常适合
- 轻量：不需要 Spring 那种重框架，一个 server.js 就能撑起整个应用

### 2.3 为什么用 Prisma 而不是直接写 SQL？

- **类型安全**：模型定义在 schema.prisma，查询结果自带类型提示
- **防 SQL 注入**：Prisma 生成的查询全部参数化
- **迁移管理**：schema 改了以后，用 `prisma db push` 或 `prisma migrate` 自动同步数据库，不用手写 ALTER TABLE
- 相比 TypeORM/Sequelize：语法更直观，社区评价最高

### 2.4 为什么 MySQL + Redis 的组合？

- MySQL：关系型数据库，数据一致性要求高（用户、笔记、分类、关联关系），SQL 查询灵活，支持全文索引
- Redis：内存数据库，速度快 100 倍以上，用于**缓存**（分类树等热点数据）和**限流计数器**
- 为什么不只用 MySQL？Redis 承担高并发读压力，MySQL 只做最终存储

### 2.5 为什么 Docker？

- 环境一致性：本地和服务器跑同样的 MySQL/Redis，避免"我机器上好好的"问题
- 一键部署：`docker-compose up -d` 一条命令拉起三个服务
- 数据卷（volume）：数据库文件持久化在宿主机，容器删了数据不丢

## 3. 关键设计决策（面试讲这些 = 展示深度）

### 3.1 双数据访问模式（USE_PRISMA 开关）

`server.js` 顶部有一个环境变量开关：

```js
const USE_PRISMA = process.env.USE_PRISMA === '1';
```

- `USE_PRISMA=1`：走 Prisma ORM（生产模式，当前生效）
- `USE_PRISMA=0`：走原始 mysql2 连接池 + 手写 SQL（早期版本，保留做应急回退）

**面试话术**："项目经历了从原生 SQL 到 ORM 的演进，我保留了双轨切换的能力，方便对比性能与应急回退。"——这展示了**渐进式重构**的思想。

### 3.2 混合部署（Docker + 宿主机）

- MySQL/Redis 用 Docker 容器跑（省去服务器上手动安装配置）
- Node 应用直接跑在宿主机 + PM2 进程守护（省去 Docker 镜像构建时间，低配服务器更省资源）

**面试话术**："数据库用 Docker 隔离环境，应用用 PM2 原生运行，这是对 2 核 2GB 低配服务器的针对性优化。"

### 3.3 前后端分离 + 静态托管

- 开发：Vite dev server (5173) 代理 `/api` 到后端 (3000)
- 生产：`npm run build` 生成 dist/ 静态文件，Express 直接托管，一个端口全搞定（SPA 路由回退到 index.html）

## 4. 数据模型全景（5 张表）

```
users ─┬── notes ──┬── note_categories（多对多关联表）
       │           └── review_cards（复习卡，笔记的 1:1）
       ├── categories（支持父子多级）
       ├── feedback（意见反馈）
       └── settings 存在 users 表的 JSON 字段里
```

| 表 | 作用 | 关键字段 |
|----|------|---------|
| users | 用户 | username, email, password_hash, role, settings(JSON) |
| notes | 笔记 | title, content, is_pinned, mastery, plan_data(JSON) |
| categories | 分类（可多级） | name, color, parent_id 自引用 |
| note_categories | 笔记↔分类多对多 | note_id + category_id 复合主键 |
| review_cards | 间隔重复复习卡 | due_date, interval, ease_factor, reps |
| feedback | 意见反馈 | content, contact |

详细设计思路见 `05-数据库设计与Prisma.md`。

## 5. 项目演进史（讲故事的素材）

真实的项目演进比简历上写的更丰满，面试时讲这个非常有说服力：

```
阶段 1：单用户笔记 CRUD（原生 SQL + mysql2）
阶段 2：分类多级树、图片上传、搜索
阶段 3：多用户 + 数据隔离（所有表加 user_id）+ Prisma ORM 化
阶段 4：JWT 鉴权、CSRF、限流、helmet 安全加固
阶段 5：间隔重复复习系统（SM-2 算法）+ 复习统计
阶段 6：功能开关体系（用户可配置的功能面板）
阶段 7：2D 知识画布（D3.js）
阶段 8：计划甘特表（CSS 定位 + 拖拽交互）
阶段 9：找回密码（邮箱验证码 + SMTP）+ 上线部署
```

每个阶段都有明确的问题和动机——这就是"业务驱动技术演进"的绝佳案例。

## 6. 面试追问预测

| 追问 | 答案要点 |
|------|---------|
| 为什么不用单体 SSR 框架（Next.js）？ | 项目是工具类应用，交互重、SEO 需求低，SPA 更合适 |
| 数据量大怎么办？ | 目前中小规模；可加索引（已有 user_id 索引）、分页（feedback 已分页）、Redis 缓存热点 |
| 多用户数据怎么隔离？ | 每个表都带 user_id 外键，所有查询都带 `where: { userId }`，ORM 层保证 |
| 并发写入怎么办？ | 单用户编辑自己的笔记，冲突概率低；更新用 updateMany + 用户条件防越权 |
| 怎么保证密码安全？ | bcrypt 加盐哈希（8 轮），数据库泄露也拿不到明文 |
| 中文搜索怎么做？ | MySQL FULLTEXT ngram 解析器，按词分词 |
