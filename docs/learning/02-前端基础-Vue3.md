# 02 · 前端基础：Vue 3 与组合式 API

> 本项目前端 100% 用 Vue 3 组合式 API（Composition API）编写。
> 读完本文你应掌握：响应式原理、ref/reactive/computed/watch、`<script setup>` 语法、组件通信。

---

## 1. 先搞懂：什么是响应式？

传统 JS 改数据 → 手动操作 DOM：

```js
let count = 0;
document.getElementById('btn').onclick = () => {
  count++;
  document.getElementById('count').textContent = count; // 手动同步！
};
```

Vue 的响应式：**数据变了，界面自动变**。

```js
const count = ref(0);   // 声明响应式数据
// 模板里写 {{ count }}，count 一变，页面自动更新
```

Vue 3 的实现原理（面试常考）：

- **Proxy 代理**：Vue 3 用 JS 的 `Proxy` 对象包装数据，拦截"读取"和"写入"操作
- **依赖收集**：当组件模板读取了某个数据 → 建立"数据 → 组件"的依赖关系
- **触发更新**：当数据被修改 → 通知所有依赖它的组件重新渲染

```
读取数据 ──▶ 收集依赖（谁在用这个数据？）
修改数据 ──▶ 通知依赖（你们要重新渲染了！）
```

## 2. 四大核心 API（本项目到处在用）

### 2.1 ref —— 单个值的响应式

```js
import { ref } from 'vue';

const count = ref(0);
count.value = 5;   // 注意：JS 里要 .value，模板里不用

const loading = ref(false);
const errorMsg = ref('');
```

### 2.2 reactive —— 对象的响应式

```js
import { reactive } from 'vue';

const state = reactive({ count: 0, name: 'tom' });
state.count++;   // 直接改属性，不用 .value
```

> 本项目统一用 `ref` 风格（即使存对象也用 ref），团队一致性更好。项目中大量出现 `ref({...})`。

### 2.3 computed —— 根据其他数据计算

**只读推导**：依赖的数据不变，结果不会重复计算（有缓存）。

```js
// src/components/NoteList.vue 的典型用法
const dueNotes = computed(() =>
  notes.value.filter(n => dueNoteIds.value.includes(n.id))
);
// dueNotes 会随 notes 或 dueNoteIds 变化自动重新计算
```

**面试点**：computed 有缓存，函数调用每次都会执行——数据量大时性能差异明显。

### 2.4 watch —— 监听数据变化

```js
import { watch } from 'vue';

// 监听某个值，变化时执行回调
watch(mode, () => {
  errorMsg.value = '';
  username.value = '';
});

// 监听多个
watch([count, loading], ([newCount, newLoading]) => {
  console.log(newCount, newLoading);
});
```

本项目典型场景（LoginView.vue）：切到"找回密码"模式时，清空所有表单字段。

## 3. `<script setup>` 语法（Vue 3.2+）

项目里所有 `.vue` 组件都是这个结构：

```vue
<template>
  <!-- HTML 结构，可以直接使用 script 里定义的变量 -->
  <button @click="increment">点击 {{ count }}</button>
</template>

<script setup>
import { ref } from 'vue';

// 这里写的变量/函数，模板里自动可用，不用 return
const count = ref(0);
function increment() {
  count.value++;
}
</script>

<style scoped>
/* scoped: 样式只对当前组件生效，不污染全局 */
</style>
```

**优点**：省掉了 Options API 的 `data/computed/methods` 分段，逻辑相关的东西写在一起。

## 4. 组件通信（本项目用到的三种）

### 4.1 Props —— 父 → 子（传数据）

```vue
<!-- 父组件 -->
<NoteCard :note="note" @delete="onDelete" />

<!-- 子组件 NoteCard.vue -->
<script setup>
const props = defineProps({
  note: { type: Object, required: true }
});
</script>
```

### 4.2 Emits —— 子 → 父（通知事件）

```vue
<!-- 子组件内：点删除按钮时通知父组件 -->
<script setup>
const emit = defineEmits(['delete']);
function onDeleteClick() {
  emit('delete', props.note.id);   // 把 id 传给父组件
}
</script>
```

### 4.3 共享状态（Store）—— 跨组件全局数据

涉及多个组件共享的数据（当前笔记、功能开关、到期笔记），用 Pinia 风格的全局 store（本项目手写的轻量版，见 03 文档）：

```js
import { useStore } from '@/store';
const store = useStore();
store.openNote(note);   // 任何组件都能操作
```

**选择原则**：
- 父子直接交互 → props/emits
- 深层或全局共享 → store
- 跨越多层但逻辑独立 → store 更干净

## 5. 生命周期与异步初始化（本项目踩过的坑）

### 5.1 onMounted —— 组件挂载后

```js
import { onMounted } from 'vue';

onMounted(() => {
  loadNotes();   // 进入页面先拉数据
});
```

### 5.2 踩坑案例：子组件拿不到初始数据（项目真实经验）

**现象**：子组件在 `onMounted` 里读 store 的功能开关，读到的是默认值。
**原因**：父组件的 `initFeatures()` 是异步的（要请求后端），子组件 `onMounted` 时请求还没回来。
**解决**：不要在 onMounted 里一次性读取，改用 `watch` 监听数据到达：

```js
watch(features, (val) => {
  if (val.ganttChart) openGantt();
});
```

**面试话术**："我遇到过一个异步初始化竞态问题——子组件挂载早于全局数据加载完成，后来改用 watch 订阅而非一次性读取解决。这类问题在 React 里是 useEffect 的常见坑，本质是数据就绪时序问题。"

## 6. 模板常用指令速查

| 指令 | 作用 | 项目示例 |
|------|------|---------|
| `v-if / v-else` | 条件渲染（不满足就不渲染元素） | `v-if="mode === 'login'"` 登录表单 |
| `v-for` | 列表渲染 | `v-for="note in notes"` 笔记卡片 |
| `@click` 等 | 事件绑定 | `@click="deleteNote(note.id)"` |
| `:class` / `:style` | 动态绑定 | `:class="{ active: mode === 'login' }"` |
| `v-model` | 表单双向绑定 | `v-model="username"` 输入框 |
| `{{ }}` | 插值 | `{{ note.title }}` |
| `ref="xxx"` | 获取 DOM 元素 | `ref="usernameInput"` 然后 `usernameInput.value?.focus()` |

## 7. 从本项目挑一段代码精读

`src/components/NoteList.vue` 核心逻辑（伪代码还原）：

```js
const notes = ref([]);              // 笔记列表（数据）
const loading = ref(false);

async function loadNotes() {
  loading.value = true;
  try {
    const data = await API.getNotes();
    notes.value = data;             // 数据一变，v-for 自动重渲染
  } finally {
    loading.value = false;
  }
}

onMounted(loadNotes);               // 进页面就加载

// 删除一篇笔记：先调 API，成功后从数组移除（界面立即消失）
async function deleteNote(id) {
  await API.deleteNote(id);
  notes.value = notes.value.filter(n => n.id !== id);
}
```

**注意 `loading` 的用法**：请求期间按钮禁用、显示"加载中"——这是所有真实项目的基本交互规范，面试可以主动提。
