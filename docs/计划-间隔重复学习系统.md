# QuickMark 间隔重复学习系统 — 发展计划方案

> 目标：把 QuickMark 从一个「记笔记的地方」升级成「帮你记住笔记的学习引擎」。
> 面向读者：熟悉 Vue3/Vite、后端较弱的同学。力求通俗易懂，代码可直接落地。

---

## 0. 一句话定位

笔记应用多的是，**能帮你「记住」笔记的笔记应用**很少。间隔重复（Spaced Repetition）就是做这件事的成熟方法——本方案把它接进 QuickMark 已有的笔记 / 双链地基上。

---

## 1. 通俗讲解：它到底是什么

### 1.1 遗忘曲线（为什么需要它）
19 世纪心理学家艾宾浩斯发现：人学完一个东西后，记忆会随时间**衰减**——一天后可能只记得 30%，一周后更少。这就是「背了又忘」的科学解释。

### 1.2 间隔重复的核心直觉
如果在「**快忘、但还没完全忘**」的时候复习一下，这次记忆就被「加固」了，而且**下一次能撑更久**。
规律是：复习间隔越来越长 —— 第 1 次学完 1 天后复习，第 2 次 6 天后，第 3 次 15 天……越往后越轻松。

### 1.3 SM-2 是什么（一句话）
SM-2 是 1980 年代 SuperMemo 提出的排程算法，也是今天 **Anki** 这类记忆软件的内核。
它做一件事：**每次复习让你打个分（0–5 分），分数决定「下次隔多久」以及「这张卡对你来说有多难」**。

### 1.4 类比：智能浇水器
把每张笔记想象成一盆植物：
- 不浇水（不复习）→ 慢慢枯死（遗忘）。
- 浇一次水（复习一次）→ 活过来，且下次能撑更久。
- **SM-2 是「智能浇水器」**：它记住每盆植物多耐旱（难度系数 EF）。耐旱的少浇（间隔长），娇气的勤浇（间隔短）。你每次浇完顺手评价「这盆好养吗」，它就越浇越准。

### 1.5 它和 QuickMark 怎么结合
- **笔记 = 学习材料**（你本来就在写）。
- **`[[quiz:问题|答案]]` = 自测卡**：在笔记里写 `[[quiz:TCP 三次握手是什么?|SYN→SYN/ACK→ACK]]`，复习时就会抽你这道题。
- **掌握度 = 知识图谱着色**：每张卡练得越熟，图谱里对应节点越「绿」，一眼看出哪块还没掌握。

## 2. 核心算法 SM-2（讲透 + 代码）

### 2.1 每张复习卡的状态（4 个字段）
| 字段 | 含义 | 初始值 |
|------|------|--------|
| `easeFactor` (EF) | 难度系数，越大间隔涨得越快 | 2.5 |
| `interval` (I) | 下次复习间隔（天） | 0 |
| `reps` (n) | 连续答对次数 | 0 |
| `dueDate` | 哪天该复习 | 今天 |

### 2.2 评分 quality（0–5）
复习时你给一个分：
- `0–2`：没记住（Again）→ **失败**
- `3`：勉强想起（Hard）
- `4`：顺利想起（Good）
- `5`：秒回（Easy）

### 2.3 更新规则（关键：quality < 3 即失败，重置）
```
if quality < 3:
    reps = 0
    interval = 1        # 明天再练
else:
    if reps == 0:  interval = 1
    elif reps == 1: interval = 6
    else:          interval = round(interval * easeFactor)
    reps += 1
    # 更新难度系数
    easeFactor += 0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02)
    if easeFactor < 1.3: easeFactor = 1.3   # 下限保护
dueDate = 今天 + interval 天
```

### 2.4 真实可跑代码（`prisma/sm2.js`，纯函数，方便单测）
```js
// SM-2 间隔重复算法 — 纯函数，无副作用，便于单测
const MIN_EF = 1.3;

/**
 * @param {{easeFactor:number, interval:number, reps:number}} card 当前卡状态
 * @param {number} quality 评分 0–5
 * @returns {{easeFactor:number, interval:number, reps:number, dueInDays:number}}
 */
export function gradeCard(card, quality) {
  let { easeFactor, interval, reps } = card;

  // 失败：重置，明天再练
  if (quality < 3) {
    return { easeFactor, interval: 1, reps: 0, dueInDays: 1 };
  }

  // 成功：按规则推下一次间隔
  if (reps === 0) {
    interval = 1;
  } else if (reps === 1) {
    interval = 6;
  } else {
    interval = Math.round(interval * easeFactor);
  }
  reps += 1;

  // 更新难度系数 EF（公式来自 SM-2 原始论文）
  easeFactor += 0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02);
  if (easeFactor < MIN_EF) easeFactor = MIN_EF;

  return { easeFactor, interval, reps, dueInDays: interval };
}
```

### 2.5 走一遍例子（一张新卡，每次都 Good=4）
- 第 1 次：reps 0 → `interval=1`，reps→1，EF≈2.5 → **1 天后**
- 第 2 次：reps 1 → `interval=6`，reps→2 → **6 天后**
- 第 3 次：reps 2 → `interval=round(6*2.5)=15` → **15 天后**
- 某次如果 Again=2：reps 清零、`interval=1` → 从头来过（但 EF 不变，难度记忆保留）

## 3. 数据模型设计（基于现有 schema）

> 现有 `Note` 模型字段：id / title / content(Text) / isPinned / position / userId / 时间戳。
> 双链解析用 `[[...]]` 正则（`src/utils/wiki-link.js:4`），`[[quiz:...|...]]` 完全复用此思路。

### 3.1 新增 `ReviewCard` 表（排程核心）
```prisma
model ReviewCard {
  id          Int      @id @default(autoincrement())
  noteId      Int      @map("note_id")
  userId      Int      @map("user_id")
  dueDate     DateTime @map("due_date")        // 哪天该复习
  interval    Int      @default(0)             // 当前间隔(天)
  easeFactor  Float    @default(2.5) @map("ease_factor")
  reps        Int      @default(0)             // 连续答对次数
  lastReviewedAt DateTime? @map("last_reviewed_at")
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @default(now()) @updatedAt @map("updated_at")

  note Note @relation(fields: [noteId], references: [id], onDelete: Cascade)
  owner User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, dueDate], name: "idx_user_due")  // 取"今日队列"高频查询
  @@map("review_cards")
}
```
> 注意：`Note` 模型需补 `reviewCards ReviewCard[]` 反向关系；`User` 补 `reviewCards ReviewCard[]`。

### 3.2 `Note` 上加 `mastery` 字段（可选，给知识图谱着色）
```prisma
mastery Int? @default(0) @map("mastery")   // 0–5，复习越熟越高
```
图谱节点按 `mastery` 着色（复用 `KnowledgeGraph.vue` 的节点渲染）。

### 3.3 不新增存储的部分
`[[quiz:问题|答案]]` **不单独存表**，每次复习时从 `Note.content` 实时正则解析（见 §6.2）。这样笔记改了，题目自动跟着改，零同步成本。

### 3.4 多用户隔离
所有查询都带 `userId`（沿用现有 dal 的 `where: { userId }` 规矩），A 用户看不到 B 的复习卡。

## 4. 功能拆解

### 4.1 MVP（最小可用，约 1 周）
**后端**
- `ReviewCard` 模型 + Prisma 迁移。
- `prisma/sm2.js`（纯函数，含单测）。
- 接口：
  - `POST /api/review/enroll/:noteId` —— 把一篇笔记加入复习（建 `ReviewCard`）。
  - `GET  /api/review/today` —— 返回 `dueDate <= 今天` 的卡片队列（含解析出的 quiz 题）。
  - `POST /api/review/:cardId/grade` —— 提交评分，调用 `gradeCard` 更新卡，并重算 `Note.mastery`。

**前端**
- 复习页 / 弹窗：依次展示今日卡片。
- 评分按钮：`Again / Hard / Good / Easy`（映射 quality 1 / 3 / 4 / 5）。
- 若卡片含 `[[quiz]]`：先显示「问题」，点一下翻面看「答案」，再评分。
- 侧边栏/顶栏角标：显示「今日还剩 N 张」。

### 4.2 进阶
- **掌握度 + 图谱着色**：`mastery` 驱动 `KnowledgeGraph.vue` 节点颜色。
- **复习统计**：连续打卡天数（streak）、近期正确率，做个小仪表盘。
- **漏复习处理**：`dueDate` 已过仍出现在队列；可选「过期越久权重越低」的轻惩罚。
- **与学习路径结合**：路线下「未掌握笔记」优先排进每日队列。

### 4.3 可选
- **每道 quiz 独立成卡**（更细粒度）：用 `noteId + 题号` 做稳定 cardId，内容变化时重算。
- **提示 / 助记**：答案里支持 `[[hint:...]]`。
- **导出 Anki 格式**（.apkg 较复杂，先做 CSV 也行）。

## 6. 关键技术点 / 坑

1. **日期比较用「日期」不是时间戳**：`dueDate` 存 `DateTime`，取今日队列用 `dueDate <= 今天 23:59` 或按 `DATE(due_date) <= CURDATE()`，避免时区/时分导致的漏卡。
2. **`[[quiz]]` 正则**（注意和 `[[标题]]` 区分）：
   ```js
   const QUIZ_RE = /\[\[quiz:([^\]|]+)\|([^\]]+)\]\]/g;
   ```
   解析出 `{ question, answer }` 数组；和 `wiki-link.js` 的 `[[...]]` 互不冲突。
3. **评分后立即重排今日队列**：前端评分后用同一个响应式数组 `splice` 掉已评卡片，角标实时减一。
4. **SM-2 写成纯函数 + 单测**：这是你练「可测试后端逻辑」的绝佳机会（Vitest/Jest）。单测覆盖：新卡序列、失败重置、EF 下限 1.3。
5. **多用户隔离**：所有 dal 查询带 `userId`，接口走现有 `requireAuth` 中间件。
6. **建卡时机**：首次「加入复习」或首次复习时建 `ReviewCard`；笔记删除时 `onDelete: Cascade` 自动删卡。

## 7. 怎么验证（测试清单）

- **单测（`sm2.js`）**
  - 新卡连续 Good(4)：间隔应为 1 → 6 → 15。
  - 中途 Again(2)：reps 归零、interval=1。
  - EF 不会低于 1.3。
- **端到端**
  1. 写一篇含 `[[quiz:Q|A]]` 的笔记 → 点「加入复习」。
  2. `GET /api/review/today` 出现该卡。
  3. 评分 Good → 卡 `dueDate` 变为明天，`Note.mastery` 上升。
  4. 知识图谱里该节点颜色变绿。

---

## 8. 推荐的最小组装

只做 **阶段 1 + 阶段 2 的「笔记级卡片」** 就能跑通完整体验：
> 写笔记 → 加 `[[quiz]]` → 加入复习 → 每日队列抽你 → 翻面自测 → 打分 → 算法排下次 → 图谱变绿。

这条线**教育价值最高、纯逻辑可单测、且逼你练一向薄弱的后端（数据模型 + 算法 + 接口）**，是最值得先动手的方向。
